## §3. 고쳐야 할 버그 — 원인까지 확정된 것들

발표 때문에 미뤄뒀던 것들입니다. **여기부터 처리하고 §4로 갑니다.**

### 1. 🔴 `guessWord`가 한 번도 실제로 추측한 적이 없다

**위치** `bot/index.ts:482~495`

```ts
const word = await generate(systemPrompt(ctx), guessWordPrompt(ctx), {
  maxTokens: 200,
  effort: 'max',      // ← llm.ts 에서 thinking.reasoning_effort:'ultra' 로 번역됨
});
if (word.length > 0) return { t: 'guessWord', word };
...
return { t: 'guessWord', word: ctx.category };   // ← 매번 여기로 떨어진다
```

**원인** Anthropic 프로토콜에서 `max_tokens`는 **본문 + 사고의 합**이다.
`effort:'max'`가 무제한 추론을 켜므로 200토큰을 사고에 전부 쓰고 text 블록이 0개로 돌아온다.
→ `word.length > 0` 실패 → **매번 주제명을 답으로 낸다.**
예외가 아니라 정상 응답이라 에러 로그도 안 남아서 오래 안 보였다.

**고치는 법** `maxTokens`를 **4096 이상**으로. `generate()` 기본값이 1536인데
가장 깊게 생각해야 할 곳만 200을 받고 있었다.

> ⚠️ 코드 주석("budget_tokens 없이 effort만 준다 — 필요한 만큼 쓰게 둔다")과
> 실제 동작이 정면으로 모순이다. 고치면서 주석도 같이 정리할 것.

### 2. 🔴 `fallbackLine`이 세 갈래 실패를 전부 삼킨다

**위치** `bot/index.ts:210~214`, `297`

```ts
const FALLBACK_LINES = ['음 뭐라 해야 하지', '아 이거 설명하기 좀 그런데', '잠깐만', '음… 애매하네'];
...
if (text.length === 0) text = fallbackLine();
```

원래 **API 키가 없을 때**를 위한 4문장 고정 풀인데, `speak()`가 `text.length === 0`이면
무조건 쓰게 되어 있어 세 경로가 전부 여기로 모인다.

```
① 검사 2회 실패 (제시어 유출 / 채팅 한 줄 아님)
② 생성 예외
③ API 키 없음
```

사용자가 *"가끔 똑같은 말 반복한다"*고 체감하던 것의 정체다.
`isEcho`는 4개 중 다른 걸 뽑으면 못 걸러낸다.

**판단 필요** — 경로별로 다르게 처리할지, 침묵으로 돌릴지, 풀을 늘릴지.

### 3. 🔴 `humanDelay`가 짧은 발언에선 항상 0

**위치** `bot/index.ts:71~72`

```ts
function humanDelay(text: string): number {
  return Math.round(3000 + text.length * 300 + Math.random() * 2000);
}
```

두세 글자면 `3900~5900ms`인데, 모델 응답이 5~6초 걸리고 `speak()`가
이미 쓴 시간을 빼므로(`index.ts:299`) **결과가 0이 된다.**

그런데 `systemPrompt`는 **"절반은 두세 글자로 끝내라"**고 지시한다.
→ *짧게 말하라고 시켜놓고, 짧은 말에는 지연이 안 걸리는 구조.*

### 4. `guessWord`만 `speak()`를 우회한다

`describe`는 이제 `speak()`를 거친다(`index.ts:418~420`). **`guessWord`만 빠져 있다.**
그래서 `leaksWord` · `looksInvalid` · `isEcho` 검사를 하나도 안 받는다.

우회하는 이유는 **`speak()`가 옵션(`maxTokens`·`effort`)을 못 받기 때문**이다.
옵션이 필요하면 보호장치를 통째로 잃는 구조 — 1번을 고칠 때 같이 볼 것.

### 5. `DEBATE_MOVES` 7번째가 검증되지 않았다

**위치** `bot/prompts.ts:115~127`

6개가 아니라 **7개**다. 마지막(자기 발언 해명)은 4444판에서 제시어가 새서 뺐다가 되살린 것인데,
같은 시점에 `secretRule`("해명할 때도 새 정보를 보태지 마세요")도 들어왔다.
**둘 중 무엇이 유출을 막았는지 확인한 적이 없다.** 주석에도 그렇게 적혀 있다.

**열린 질문 — 이게 첫 번째로 답해야 할 것**
> 무엇을 학습 기준으로 볼 것인가

*"B가 의심스러웠다"*로는 무엇을 고칠지 알 수 없지만

## §6. 지켜야 할 규칙

- **프롬프트는 경향을 만들 뿐 보장하지 않는다.**
  반드시 지켜져야 하는 것은 **코드로 검사한다.** 기획서 v3.0의 핵심 결론이고,
  프롬프트로 두 번 막은 규칙이 두 번 다 뚫린 실측이 근거다.
- **`packages/shared-types`는 잠겨 있다.** 직접 고치지 말고 CTO(김정현)에게 알린다.
  하루에 세 사람이 같은 필드를 각자 추가한 일이 실제로 있었다.
- **고친 것은 `김정현-logs` 채널에 한 줄씩** 남긴다. 같은 것을 두 사람이 고치는 걸 막기 위함이다.
- **주석은 무엇을 하는지가 아니라 왜 그렇게 했는지**를 적는다.
  코드를 읽으면 알 수 있는 것은 안 적는다.
- **최적화는 측정한 것만 손댄다.** 느리다고 느낀 것과 실제로 느린 것은 다르다.
